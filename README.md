## 一、启动流程说明

### 1. 引导加载器阶段 (Bootloader)
- **bootasm.S**: BIOS加载引导扇区到0x7C00，初始化16位实模式，启用A20地址线，切换到32位保护模式
- **bootmain.c**: 从磁盘读取ELF格式的内核镜像，验证ELF头部，加载内核程序段到内存
- **引导扇区限制**: 必须 ≤ 510字节，最后2字节为魔数0x55AA

### 2. 内核入口阶段
- **entry.S**: 内核入口点，初始化页表，启用分页机制，设置栈指针，跳转到main函数
- **页表初始化**: 使用entrypgdir建立初始页表映射

### 3. 内核初始化阶段
- **main.c**: 内核主函数，初始化控制台、内存管理、进程管理等子系统
- **启动流程**: bootblock → bootasm.S → bootmain.c → entry.S → main()

## 三、遇到的问题及解决办法
### 问题1：编译错误 struct file has no member named 'fd'
- 现象：
- text
- sysfile.c:92:57: error: 'struct file' has no member named 'fd'
- 原因：xv6 的 struct file 定义中没有 fd 字段，文件描述符是数组索引，不在结构体内。
- 解决方法：删除 f->fd 的打印，只打印 n 参数。
### 问题2：引导扇区大小超限
- 现象：
- text
- boot block too large: 625 bytes (max 510)
- 原因：在 bootmain.c 中添加过多打印代码，导致引导扇区超过512字节限制。
- 解决方法：引导阶段保持代码精简，使用注释替代功能代码。

## 四、实践心得
- 通过本次 xv6 内核机制实践，我对操作系统的核心机制有了更深入的理解。
- 关于系统调用：之前对系统调用的理解停留在"用户态到内核态的切换"这一抽象概念上。通过实际添加系统调用并跟踪执行路径，我真正理解了系统调用的完整流程：用户程序通过 usys.S 中的汇编代码触发 int 中断，CPU 切换到内核态，syscall.c 根据系统调用号分发到具体实现函数，执行完成后通过 iret 返回用户态。这个过程中需要管理寄存器的保存与恢复、参数传递、返回值处理等细节。
- 关于调度机制：在 scheduler() 中添加日志后，我观察到 xv6 采用简单的轮转调度算法。所有可运行进程被依次调度，每个时间片内运行一个进程。通过在 switch 前后添加打印，我可以看到进程上下文切换的具体时刻。调度器遍历进程表，找到状态为 RUNNABLE 的进程，切换到该进程执行。
- 关于内存管理：通过记录 kalloc() 的分配地址，我观察到 xv6 使用链表管理空闲页，分配时从链表头部取出，释放时插回链表。初始分配地址从高地址向低地址增长，这与某些系统的分配策略不同。通过观察地址变化，发现内存分配并不是完全连续的，存在一定的复用情况。
- 关于实践收获：这次实验让我体会到阅读操作系统源代码的重要性。xv6 虽然代码量不大，但包含了操作系统核心功能的完整实现。通过在关键路径添加调试输出，可以直观地观察到系统运行时的行为。这种"动手改代码"的学习方式比单纯看书有效得多。同时，我也学会了使用 grep 搜索代码、使用 nano 编辑文件、使用 git 进行版本管理等实用技能。
- 遇到的困难：最大的困难是理解 xv6 的代码结构。刚开始时很难找到需要修改的文件和函数，但通过 grep 搜索和阅读代码注释，逐渐熟悉了代码组织方式。Git 的使用也是需要练习的，学会了分支管理、提交规范等基本操作。
- 后续学习：接下来可以尝试 xv6 的第三层任务，如实现生产者-消费者模型，进一步理解同步机制。也可以尝试其他操作系统实验，如 MIT 6.S081 的完整课程。
